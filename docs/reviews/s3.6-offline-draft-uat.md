# S3.6 Offline ActivityReport Draft — Operational UAT Matrix

Status: implementation validation companion for S3.6.

This document separates **automated evidence already exercised by CI** from **operator/browser checks that require an actual authenticated browser session and network toggling**. A checked-in matrix is not evidence that a human browser UAT was executed.

## Scope

S3.6 supports one narrow degraded-connectivity scenario:

1. the authenticated application has already loaded a canonical draft ActivityReport;
2. connectivity is lost or unstable;
3. the user continues editing only the report's editable text/count fields;
4. the browser keeps an account-scoped temporary working copy;
5. reconnect synchronization either applies exactly once or stops on a server-version conflict.

Out of scope and intentionally online-only:

- Session prepare/start/end/cancel;
- SessionIssueObservation creation;
- Observation → Incident promotion;
- ActivityReport submit, request-revision, reopen, and verify;
- manual backfill creation;
- attachment upload/download or any blob queue;
- full application boot/deep-link while completely offline.

## Acceptance matrix

| ID | Scenario | Expected result | Evidence |
| --- | --- | --- | --- |
| UAT-01 | Edit a loaded draft while online and press sync | Server applies one patch, report version increases by one, local cache clears | Automated API + web contract tests |
| UAT-02 | Lose network after opening an editable draft, change text/count fields | Form remains editable; account-scoped working copy is stored locally; no claim of canonical save | Automated cache tests; **operator browser toggle required for UX** |
| UAT-03 | Retry the same pending mutation after an ambiguous/network failure | Same clientMutationId/base/payload is replayed safely; no second version bump or duplicate audit event | Automated API integration test |
| UAT-04 | Reuse a clientMutationId with different content | Server rejects with ACTIVITY_REPORT_SYNC_MUTATION_REUSED | Automated API integration test |
| UAT-05 | Another client changes the report after the offline draft base version | Sync returns ACTIVITY_REPORT_OFFLINE_SYNC_CONFLICT and preserves newer server data | Automated API integration test |
| UAT-06 | Conflict touches the same field on local and server | UI identifies the conflicting field and performs no automatic overwrite | Automated three-way conflict test; **operator browser check recommended** |
| UAT-07 | User selects “Gunakan Versi Server” | Local working copy is cleared and editor shows canonical server values | Source/UI regression coverage; **operator browser check required** |
| UAT-08 | User selects “Rebase Draft Lokal” | Only locally changed fields are reapplied over latest server snapshot; untouched server changes remain; new clientMutationId is generated | Automated rebase tests; **operator browser check required** |
| UAT-09 | Attempt submit while offline | Submit is blocked; local draft remains available | Source/UI regression coverage; **operator browser toggle required** |
| UAT-10 | Attempt attachment upload with local text changes pending | Upload is blocked until text draft is synchronized | Source/UI regression coverage; **operator browser check required** |
| UAT-11 | Attempt attachment upload/download offline | Action is blocked; no attachment/blob is placed into local queue | Source/UI regression coverage |
| UAT-12 | Attempt Session lifecycle action offline | Action is blocked because source/availability/lifecycle validation remains server-authoritative | Source/UI regression coverage; **operator browser toggle required** |
| UAT-13 | Attempt Observation/Incident workflow offline | Action is blocked; no local Incident/Observation queue is created | Source/UI regression coverage |

## Operator browser procedure

Use a non-production test School and a dedicated test account.

1. Open /sessions, finish or select a canonical Session whose ActivityReport is draft, and open the editor.
2. Record the displayed report number and version context.
3. In browser DevTools, switch network to Offline only after the draft is loaded.
4. Change at least one common-content field, attendance notes, and one type-specific field.
5. Confirm the UI shows **Offline** and **Draft Lokal** rather than claiming a server save.
6. Close and reopen the editor without changing authenticated identity; confirm the working copy is restored.
7. Return network to Online and use **Sinkronkan Sekarang**.
8. Confirm the draft becomes **Tersinkron**, server values match the working copy, and one version increment occurred.
9. Repeat with a second browser/client that changes one server field before reconnecting the first client.
10. Confirm the first client enters **Konflik** and does not silently overwrite.
11. Test both conflict decisions: **Gunakan Versi Server** and **Rebase Draft Lokal**, reviewing values before the next sync.
12. While offline, confirm Session lifecycle, Observation/Incident, submit/verify/revision/backfill, and attachment controls remain blocked.
13. After a clean sync, upload one allowed attachment online and verify report version refreshes without losing draft text.

Record test account, browser version, environment commit SHA, date/time, observed versions, and screenshots/logs in the deployment/UAT record. Do not place student-sensitive data in screenshots.

## Exit rule

S3.6 code can be considered implementation-complete when CI is green and this matrix is present. Production rollout still requires the operator/browser scenarios marked above to be executed in the target environment; failures become defects rather than reasons to weaken the server-authority boundary.
